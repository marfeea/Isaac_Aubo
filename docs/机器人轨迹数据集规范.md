## 1. 目标与适用范围

本规范用于教师强化学习策略的轨迹采集，并支持后续的：

- 世界模型训练。
- 视觉模仿学习和离线强化学习。
- 状态、视觉、语言和多模态控制模型。
- 单臂、双臂与多机器人轨迹。
- 仿真、真实机器人及 sim-to-real 对比。
- RLDS、LeRobot、Robomimic 等外部生态格式。

所有新增或修改的数据采集、序列化、数据加载、格式转换、数据校验、标注、划分和统计逻辑都必须遵守本规范。

## 3. 强制设计原则

1. **显式语义**：不得仅保存无字段说明的匿名拼接向量。
2. **状态转移完整**：主数据必须能构造 `(S_t, A_t, R_t, S_{t+1}, delta_t, done_t)`。
3. **部署信息隔离**：部署时可获得的观测与仿真/教师特权真值必须分开。
4. **不丢失动作链路**：同时保存策略原始输出、物理命令、控制器目标和实际执行结果。
5. **时间戳优先**：不同传感器不强制共享帧率；先保留原始时间戳，后生成对齐视图。
6. **无损主数据**：归一化、图像缩放、视频转码和时间重采样属于派生数据。
7. **可追溯**：数据必须指向代码、配置、资产、教师 checkpoint 和随机种子。
8. **向后兼容**：已发布数据不得被静默改义；破坏性变更必须升级主版本并提供迁移逻辑。

## 4. 时序语义

一条轨迹定义为：

\[
\tau = \{(S_t, A_t, R_t, S_{t+1}, \Delta t_t, D_t)\}_{t=0}^{T-1}
\]

其中：

- `Frame[t]` 保存 `S_t`，每条轨迹有 `T + 1` 个 Frame。
- `Transition[t]` 保存 `A_t`、动作执行后产生的 `R_t`、`delta_t` 和终止信息，每条轨迹有 `T` 个 Transition。
- `Transition[t].source_frame_index == t`。
- `Transition[t].target_frame_index == t + 1`。
- 最后一个 Frame 只有观测，没有后续动作。
- `terminated` 表示环境终止，`truncated` 表示超时或外部截断，两者不得混同为单一 `done`。
- `success` 是任务结果，不等同于 `terminated`。

## 5. 数据模型

### 5.1 Dataset 元数据

```yaml
dataset_id: aubo_teacher_v1
schema_name: AUBO-RobotTraj
schema_version: 1.0.0
domain: simulation
created_at: 2026-07-03T00:00:00+08:00
git_commit: null
isaaclab_version: null
robot_family: AUBO
coordinate_convention: right_handed
quaternion_order: wxyz
clocks:
  simulation_hz: 120.0
  policy_hz: 4.0
  camera_hz: 30.0
```

必填信息：

- 数据集唯一 ID 和 schema 版本。
- 代码 commit、仿真器版本和机器人型号。
- 配置、资产、控制器和 checkpoint 的 SHA256。
- 坐标系手性、四元数顺序和默认浮点精度。
- 各时钟的名义频率、时钟源和时间戳单位。

### 5.2 Task

```yaml
task_id: reach_target_v1
task_suite: aubo_reaching
name: 末端到达目标
instruction: 将末端移动到指定目标位置
definition:
  type: isaaclab_config
  uri: configs/RLcfg.py
  sha256: null
success_criteria_version: 1
```

若任务由 PDDL、BDDL、USD 场景或其他文件定义，必须保存类型、相对路径和内容哈希。

### 5.3 Episode

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `episode_id` | string | 全局唯一，稳定不变 |
| `task_id` | string | 引用 Task |
| `scene_id` | string | 场景和工位布局标识 |
| `initial_state_id` | string | 可复现的初始状态标识 |
| `seed` | int64 | 环境随机种子 |
| `teacher_id` | string | 教师策略和 checkpoint 引用 |
| `num_transitions` | int32 | 动作数量 `T` |
| `start_timestamp_ns` | int64 | 回合起始时间 |
| `end_timestamp_ns` | int64 | 回合结束时间 |
| `invalid` | bool | 中断写入、传感器缺失等不可用数据 |
| `split` | string | `train/validation/test` 或自定义评测分组 |

每个 Episode 必须同时保存：

- 教师算法、checkpoint 哈希、确定性模式和动作采样设置。
- 域随机化、物体初始位姿、质量、摩擦和控制器参数快照或快照哈希。
- 任务指令、任务结果和终止原因。

### 5.4 Frame

```yaml
episode_id: ep_000001
frame_index: 0
timestamp_ns: 0
observation:
  deployable:
    robots:
      arm0:
        joint_position: []
        joint_velocity: []
        joint_effort: []
        ee_position: [0.0, 0.0, 0.0]
        ee_orientation_wxyz: [1.0, 0.0, 0.0, 0.0]
        ee_linear_velocity: [0.0, 0.0, 0.0]
        ee_angular_velocity: [0.0, 0.0, 0.0]
    cameras:
      workspace:
        rgb_ref: null
        depth_ref: null
        calibration_id: workspace_camera_v1
        world_T_camera: []
  task:
    instruction_id: reach_target_v1
privileged:
  object_poses: {}
  object_velocities: {}
  target_pose: null
  simulator_state_ref: null
  semantic_segmentation_ref: null
  instance_segmentation_ref: null
```

`observation.deployable` 只允许放入预计在真实部署时可获得的数据。物体真值位姿、目标真值、仿真内部状态、语义/实例分割默认属于 `privileged`。

### 5.5 Transition

```yaml
episode_id: ep_000001
transition_index: 0
source_frame_index: 0
target_frame_index: 1
start_timestamp_ns: 0
end_timestamp_ns: 250000000
delta_t_s: 0.25
action:
  policy_raw: [0.0, 0.0, 0.0]
  command:
    representation: delta_position
    frame: arm0/base
    unit: meter
    ee_delta_position: [0.0, 0.0, 0.0]
  controller_target:
    ee_target_pose: null
    joint_position_target: null
  executed:
    ee_delta_position: null
    joint_delta: null
  diagnostics:
    clipped: false
    ik_success: true
    control_latency_ms: null
reward:
  terms: {}
  total: 0.0
  discount: 1.0
flags:
  success: false
  terminated: false
  truncated: false
  termination_reason: null
```

### 5.6 Sensor Stream

大容量传感器与低维 Frame 解耦，每个 stream 至少包含：

- `stream_id`、`sensor_id`、`modality`、`dtype`和 `shape`。
- 每帧 `timestamp_ns`、`frame_number` 和数据引用。
- 丢帧、过期帧和无效像素标记。
- 标定 ID；腕部相机等动态外参还必须保存每帧位姿或可验证的变换链。

深度必须保留真实物理量和无效值 mask，不得用彩色深度可视化图代替。

### 5.7 Event Stream

接触、碰撞、安全限位、IK 失败和人工中断使用独立事件流：

```yaml
episode_id: ep_000001
timestamp_ns: 0
event_type: contact
source_entity: arm0/flange
target_entity: target
payload:
  force_world: [0.0, 0.0, 0.0]
  torque_world: [0.0, 0.0, 0.0]
  impulse: 0.0
```

原始高频事件不得被每个策略步的单一布尔值取代。可额外生成控制周期内的最大力、积分冲量和接触次数。

## 6. 坐标系、单位与动作语义

### 6.1 默认约定

- 位置和位移：米 `m`。
- 时间：秒 `s`；原始时间戳为 `int64 ns`。
- 角度：弧度 `rad`。
- 线速度：`m/s`。
- 角速度：`rad/s`。
- 力和力矩：`N` 和 `N·m`。
- 位姿四元数：`wxyz`，必须声明变换方向，例如 `world_T_ee`。
- 主数据低维浮点默认为 `float32`；特殊精度需求在 schema 中声明。

### 6.2 动作必填语义

每个动作字段必须声明：

- `representation`：`absolute_position`、`delta_position`、`velocity`、`effort` 或其他明确类型。
- `frame`：`world`、`robot_base`、`end_effector`、`camera` 等具体 frame ID。
- `unit`。
- `normalized`、归一化范围和反归一化参数。
- 夹爪的正负方向、连续/离散定义。
- 截断、限幅、安全投影和控制器失败结果。

关节位置和关节速度的测量值属于状态。只有关节位置目标、速度指令、力矩指令或关节增量才属于动作。

## 7. 奖励语义

每个 step 奖励项必须保存：

```yaml
ee_progress:
  raw_value: 0.0
  weight: 80.0
  time_scale: 0.25
  contribution: 0.0
```

其中：

\[
contribution = raw\_value \times weight \times time\_scale
\]

如果某个奖励项不使用时间缩放，`time_scale` 显式记为 `1.0`。必须同时保存：

- `reward_config_hash`。
- 每项原始值、权重、时间缩放和最终贡献。
- 每步 `total_reward`。
- Episode 级别的未折扣回报、折扣回报和每项累计值。

任务成功、安全性和行为质量是独立评估结果，不得只根据总奖励反推。

## 8. 文字与结果标注

指令与结果描述必须分开，避免在策略训练时将结果泄漏到输入。

### 8.1 指令标注

- `instruction`：回合全程有效的任务指令。
- `instruction_variants`：同语义表述，保留生成方式和审核状态。
- `subtask_spans`：长时域任务中的子任务文本与起止时间。

### 8.2 结果标注

```yaml
status: success
success_auto: true
success_human: true
primary_failure_reason: null
secondary_failure_reasons: []
failure_step: null
description: 末端平稳到达目标区域
annotator_type: human
annotator_id: null
annotation_version: 1
confidence: 1.0
```

`status` 限定为：

- `success`
- `partial`
- `failure`
- `invalid`

`primary_failure_reason` 至少支持：

- `timeout`
- `out_of_workspace`
- `self_collision`
- `environment_collision`
- `target_hard_contact`
- `ik_failure`
- `controller_saturation`
- `wrong_object`
- `wrong_order`
- `sensor_invalid`
- `human_abort`
- `unknown`

结构化枚举是统计与筛选依据，自由文本只用于补充。标注以附加表形式管理，不因新增标注而改写原始轨迹。

## 9. 物理存储布局

```text
<dataset_root>/
├── meta/
│   ├── dataset.json
│   ├── schema.json
│   ├── sensors.json
│   ├── tasks.parquet
│   └── episodes.parquet
├── data/
│   ├── frames/chunk-*.parquet
│   ├── transitions/chunk-*.parquet
│   └── events/contact-*.parquet
├── sensors/
│   ├── workspace_rgb/chunk-*.zarr
│   ├── workspace_depth/chunk-*.zarr
│   ├── wrist_rgb/chunk-*.zarr
│   └── wrist_depth/chunk-*.zarr
├── annotations/
│   ├── trajectory_labels.parquet
│   └── subtask_spans.parquet
├── artifacts/
│   ├── configs/
│   ├── asset_hashes.json
│   └── teacher_checkpoints.json
├── manifests/
│   └── checksums.sha256
└── exports/
    ├── lerobot_v3/
    ├── rlds/
    └── robomimic/
```

存储规则：

- 低维时序、Episode 和标注使用 Parquet。
- RGB 主数据使用 `uint8` 无损分块存储。
- Isaac `distance_to_image_plane` 主数据使用 `float32 meter` 及无效值 mask；只有原始设备本身输出毫米整数时才使用 `uint16 mm`。
- 视频编码、图像缩放、归一化和 action chunk 作为 `exports/` 或其他派生目录。
- 不使用“每帧一个图片”或“每轨迹一个小文件”作为大规模数据集的最终布局。
- 每个 shard 在完成写入后原子提交；未完成 shard 不进入可训练 manifest。

## 10. 多频率同步

1. 每个传感器和控制流使用自身原始时间戳。
2. 同一 Episode 中所有时间戳必须可映射到同一单调时钟。
3. 对齐策略必须记录在派生数据元数据中，例如 `nearest`、`previous`、`linear` 或 `window_aggregate`。
4. 动作保持、图像重采样和关节状态插值必须分别声明，不得默认使用同一插值方法。
5. 世界模型数据集必须输出 `delta_t`，不得假设丢帧后的间隔仍等于标称周期。

## 11. 当前 AUBO 项目映射

当前 `configs/RLcfg.py` 中：

- 仿真频率为 `120 Hz`。
- `decimation = 30`，策略控制频率为 `4 Hz`。
- Episode 时长为 `40 s`，最大动作数为 `160`。
- 当前策略动作是归一化的三维末端位移，每轴缩放 `0.01 m`，每周期位移模长上限 `0.01 m`。
- 当前观测包含关节位置/速度、末端位置/线速度、目标位置和指向目标的向量。

当前动作映射：

| 字段 | 来源 | 语义 |
| --- | --- | --- |
| `action.policy_raw` | PPO 直接输出 | `[-1, 1]` 范围的三维向量 |
| `action.command.ee_delta_position` | `policy_raw * pos_scale` 并限幅 | AUBO 根/基座坐标系下的末端位移命令，单位 `m` |
| `action.controller_target.ee_target_pose` | 当前末端位姿与命令合成 | Lula IK 的绝对末端目标 |
| `action.controller_target.joint_position_target` | IK 输出 | 下发给关节位置控制器的目标 |
| `action.executed.ee_delta_position` | 下一 Frame 与当前 Frame 差值 | 实际执行的末端位移 |

当前奖励项：

- `ee_progress`
- `ee_distance_exp`
- `success`
- `action_far_near`
- `step_penalty`
- `action_l2`
- `action_rate_l2`
- `out_of_workspace_penalty`
- `target_contact_penalty`
- `collision_penalty`

`configs/scene_cfg.py` 已定义两台 AUBO 和 `640 x 480` 相机，相机可输出 RGB、`distance_to_image_plane`、法线、语义分割和实例分割。数据 schema 从首版即使用 `arm0/arm1` 和具名相机键，不将顶层结构写死为单臂。

建议原始采集频率：

- 策略 Transition：`4 Hz`。
- RGB-D：根据当前 `render_interval = 4` 的名义渲染节拍按 `30 Hz` 采集，最终以实际时间戳为准。
- 关节、接触和安全事件：保留 `120 Hz` 原始流，另行生成 `4 Hz` 统计视图。

## 12. 数据划分与防泄漏

- 默认按任务、场景、物体实例、目标区域或随机种子组划分，不随机打散相邻帧。
- 同一 Episode 只能属于一个 split。
- 来自同一初始状态或只有轻微摄像头扰动的轨迹不应跨训练与测试集。
- 归一化统计只使用训练集计算。
- 教师特权状态默认不进入学生策略输入；如用于辅助损失，训练配置必须显式列出。

## 13. 版本、迁移与派生数据

Schema 使用语义化版本：

- `PATCH`：文档澄清或不改变机器解析的修正。
- `MINOR`：可选字段、新 modality 或向后兼容的枚举扩展。
- `MAJOR`：字段删除、重命名、单位/坐标系/时序语义改变或不兼容的存储变更。

数据发布后：

1. 不原地改写已发布 shard。
2. 迁移产生新数据集 ID 或新版本目录。
3. 保存源数据 ID、源 schema 版本、转换程序 commit、参数和时间。
4. 不可逆转换必须标记 `lossy: true` 和具体丢失内容。
5. 训练程序记录实际使用的 dataset manifest 哈希，不只记录目录路径。

## 14. 验收规则

每个数据 shard 进入可训练 manifest 前必须通过：

### 14.1 结构校验

- Dataset、Task、Episode、Frame 和 Transition 必填字段完整。
- 每条轨迹满足 `num_frames = num_transitions + 1`。
- Frame/Transition 索引连续，引用不越界。
- ID 唯一，外键都可解析。

### 14.2 时间校验

- 每个 stream 时间戳严格单调。
- `delta_t_s > 0`，且与始末时间戳一致。
- 丢帧和超阈值时间差被显式记录，不静默补帧。

### 14.3 数值校验

- 必要字段无 NaN/Inf，可缺失字段有 validity mask。
- 四元数归一化，旋转矩阵符合右手坐标系。
- 观测和动作不超出 schema 声明的形状和物理范围。
- `reward.total` 与各 contribution 之和在浮点容差内一致。
- RGB、Depth 和 mask 的 dtype、分辨率与标定一致。

### 14.4 语义校验

- 动作包含 representation、frame、unit 和 normalization 信息。
- 观测测量不得误存到 action。
- `terminated`、`truncated`、`success` 和 `invalid` 语义互不替代。
- 部署观测和 privileged 数据边界正确。
- 失败 Episode 具有结构化失败原因或显式 `unknown`。

### 14.5 可追溯校验

- 配置、资产、checkpoint、shard 和 manifest 哈希完整。
- 从任一训练 batch 可追溯到 Episode、源 shard 和生成配置。
- 格式导出可追溯到源数据和转换器版本。

## 15. 数据逻辑修改流程

修改数据相关代码或配置时：

1. 先阅读本规范和项目工程修改规范。
2. 识别改动属于采集、schema、存储、转换、标注、加载、划分、统计还是校验。
3. 列出受影响的字段、时序、单位、坐标系和外部导出器。
4. 如需改变 schema，先更新本文档、版本号和迁移策略，再修改代码。
5. 主数据采集与模型特定预处理分离；预处理写入新派生数据。
6. 为新字段增加 schema、数值、时间和回放验证。
7. 运行最小采集回放，验证 `S_t -> A_t -> S_{t+1}` 和奖励对齐。
8. 检查原生格式和所有受影响导出格式。
9. 在交付中说明 schema 版本影响、兼容性、迁移和验证结果。

任何代码不得通过硬编码匿名向量索引、默认坐标系或默认时间对齐来绕过本规范。

## 16. 外部格式导出

### 16.1 RLDS / Open-X

- Episode 元数据映射为 RLDS Episode metadata。
- `Frame[0]` 映射 `is_first`。
- 最后 Frame 映射 `is_last`，根据终止语义设置 `is_terminal`。
- 动作和奖励从 Transition 映射，导出器必须测试末帧语义。

### 16.2 LeRobot v3

- 低维 Frame/Transition 物化为 Parquet 行。
- RGB 转码为按相机分片的 MP4，记录编码参数和源帧映射。
- `task` 来自任务指令，不得使用轨迹结果描述代替。
- Episode 边界通过 metadata 映射，不依赖文件边界。

### 16.3 Robomimic

- `obs = Frame[t].observation`。
- `next_obs = Frame[t+1].observation`。
- `actions/rewards/dones` 来自 `Transition[t]`。
- 导出归一化动作时同时保存反归一化元数据。

外部格式不支持的字段必须在导出报告中列出，不得静默丢弃。
